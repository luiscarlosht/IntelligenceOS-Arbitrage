# Prepare an offline Amazon-first sourcing pilot

Amazon selection now produces persisted, versioned targets and up to ten Walmart
ZIP 76063 search jobs before retailer collection. Identifier ambiguity, exact pack
requirements, unknown costs and every search outcome remain visible. Independent
matching and conservative profitability reuse the existing evidence, economics
and Excel pipeline; browser claims cannot establish an exact or profitable match.

This adds only the target/job module, tests, fictional fixture/export and pilot
documentation. Existing retailer-first behavior, pending operations, database
contents, Sheets intake ownership and running sessions are preserved. New broad
Walmart campaign preparation is paused in the pilot plan. No live executor is
added or enabled.

The reviewed Keepa plan uses one cached history lookup, one minimum Finder page of
50 ASINs and up to ten cached detail lookups: at most 12 requests, reserving 22
documented tokens. Provider billing cannot be hard-capped by this client. API
entitlement, plan price, private key entry and permission to retain provider data
remain operator prerequisites. No credentials, live provider/browser requests,
Sheets edits, purchases, email, scheduling, merge or deployment were performed.

Validation: 11 new contract/integration tests; the existing full checkout suite
and both offline sample modes; reproducible sample export; compatibility tests
against the published real-data evidence base. Exact final counts are recorded
in the draft PR and delivery message.

Publication base: `milestone/real-data-pilot`. The checkout's current parent
`6b10bcf6c7182990b5f0d7e1d37224c9e1d81f1a` is not published on GitHub.
Using the published compatible evidence base keeps this draft limited to the six
new pilot files, without uploading unrelated unpublished work. Local integration
was also checked on the current checkout; the remote draft has a different parent.
Retargeting/integration with newer unpublished milestones is a separate review step.
